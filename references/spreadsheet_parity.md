# 电子表格：界面可达性（UI Parity）与边界情况

本 skill 是**直接写工作簿快照**，绕过界面。因此「规格里能写」不等于「界面上有」。

> **判断准则**：任何**界面无入口**的状态，交付后用户在界面上既看不到入口、也改不回来——只能回到 skill 改。这是最容易让使用者困惑的地方，必须先识别再决定是否使用。

**两个离线工具**（都不访问网络、不写数据）：

```bash
cd scripts
python spreadsheet.py defaults                  # 全量 105 项：类型 / 默认值 / 界面位置 / 可达性
python spreadsheet.py defaults --key rowCount   # 按关键字查单项默认值
python spreadsheet.py lint --file spec.json     # 写入前查风险（create/edit 内置同一守卫）
```

默认值完整清单见 [spreadsheet_defaults.md](spreadsheet_defaults.md)（由 `defaults --markdown` 生成）；**不确定某项默认值时先查命令，不要凭印象**。

## 一、界面入口的构成（先认清边界）

产品的电子表格界面**没有传统的顶部菜单栏**（文件 / 编辑 / 视图… 那一排不显示）。可用入口只有三处：

1. **功能区（Ribbon）**
   - 插入：透视表、明细表、链接、批注
   - 历史：撤销 / 重做、格式刷、清除
   - 字体：字体、字号、边框、加粗、斜体、删除线、下划线、文字颜色、背景色、**斜线格**
   - 版式：水平对齐、垂直对齐、自动换行、合并单元格
   - 数字格式：格式面板、百分比、货币、增加小数、减少小数
   - 数据：**冻结、筛选、排序、数据验证、条件格式**、函数
   - 工具：表格、快捷键面板、查找替换
   - 查询组件
2. **右键菜单**
   - 工作表标签：重命名、标签颜色、隐藏、复制
   - 单元格：插入 / 删除行列、隐藏行列等
3. **单元格内编辑**：值、公式、富文本

**推论**：只挂在菜单栏里的功能，界面上等于不存在。判断可达性要按上表逐项核对，**不能按"常规电子表格软件通常有"去推断**。

## 二、三档可达性

| 档位 | 含义 | 处理 |
|------|------|------|
| ✅ **界面可编辑** | 界面上能创建、也能修改 | 放心使用 |
| ⚠️ **界面受限** | 能创建，但只能按界面的方式改，或有前提条件 | 交付时说明前提 |
| ⛔ **界面无入口** | 只有写快照才能产生；界面既不能创建也不能修改 | 默认不用；确需使用时必须告知用户 |

### 原样透传（本 skill 不校验、不补默认值）

下列字段的结构与默认值由产品定义，脚本**原样写入**，写错会在渲染时才暴露：

- `conditionalFormats` 中 `dataBar` / `colorScale` / `iconSet` 的规则体（颜色、阈值、图标集等）
- 明细表 `customFilter` 的内部结构
- 数据验证中少数内核字段（如 `custom` 的公式细节）

**稳妥做法**：这类复杂规则先在界面配一条，用 `get-edit --id` 取回快照作为参照，再改写进规格。

> 如实告诉用户在界面完成即可，**不要假装能做到，也不要用近似写法硬凑**。

### C. 界面无入口（仅快照可达）

| 项 | 原因 | 写入后果 |
|----|------|----------|
| `cells.type`（强制文本 / 数值） | "文本转数字"被隐藏，也没有"转文本" | **不可逆**；用户无法在界面换算 |
| `sheets[].showGridlines = false` | 开关原在菜单栏，菜单栏不显示 | 无法在界面恢复网格线 |
| `sheets[].rightToLeft = true` | 无对应开关 | 无法在界面改回 |
| 保护 / 单元格权限 | 界面菜单全部隐藏 | 不要写 |
| `theme` | 主题只是样式集合，界面无"主题"概念 | 无影响（样式本身可逐个改） |

## 四、五类「界面不会产生」的状态（`lint` 会拦）

1. **合并区内除左上角外还有值**（`error`）——界面上合并单元格会**清空**左上角以外的内容，产品永远不会留下这种状态；写进去的值不会显示，用户也看不到它存在。
2. **相互重叠的合并区**（`error`）——界面上无法产生。
3. **强制值类型**（`warn`）——界面无入口，写入后不可逆。
4. **从右到左 / 关闭网格线**（`warn`）——见上表 C。
5. **明细表 `resultLimit` 超过服务端上限**（`warn`）——默认上限 100000，超出会被截断，与实际取数条数不一致。

## 五、结构性边界

- **筛选会隐藏整行**：同一个工作表上下叠放多个数据块时，某一处筛选会把另一块的相关行也隐藏（数据未删除，但看着像丢了）。多块数据建议**分工作表**，或上下排列且**行范围不重叠**。
- **明细表会覆盖手工内容**：渲染块占据的区域不要放手工单元格或合并单元格。
- **明细表 / 透视表块内部值不可改**：展示样式可改，值跟随数据集；要改数据请改数据集。
- **预览态只读**：下拉写入、表头筛选、查询组件只在**编辑态**生效，预览浮层下不可交互——产品设计如此。
- **`edit` 是整份覆盖**：`edit` 用新规格整体替换 `sheetData`。若用户在建表后已在**界面改过**内容，直接 `edit` 会把这些改动抹掉。此时应先 `get-edit` 取回当前编辑稿并在其上合并，或改由用户在界面调整。
- **合并 + 冻结**：合并区域跨越冻结线时显示可能异常，建议先定冻结再定合并，或避免交叉。

## 六、交付话术

- 用了 ⛔ 类能力时：**"XX 列 / 开关在界面上没有入口，以后要调整请让我改，或重新生成。"**
- 预置了筛选条件时：**"表格打开时已按 XX 筛选，改条件点表头筛选按钮。"**
- 有明细表时：**"明细表数据跟着数据集走，改数据请改数据集；表内单元格的值改不了。"**
- 一律提示：**"下拉、筛选、查询组件的交互请在编辑态使用，预览是只读的。"**
