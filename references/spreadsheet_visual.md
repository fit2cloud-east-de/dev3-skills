# 电子表格视觉规范

在「字段与结构正确」之外，电子表格须同时满足本节的**色彩、层级、对齐、留白**要求。结构化字段以 [spreadsheet.md](spreadsheet.md) 为准；本节约束「怎么排、怎么配色、怎么让报表像成品」。

## 1. 设计令牌

### 色彩角色（一套表只用一套色系）

| 角色 | 用途 | 约束 |
|------|------|------|
| 主色 | 文档标题、区块标题、主结构线、合计行字色 | 一套表仅一个主色 |
| 主色浅底 | 表头底、合计行底 | 主色同色系 8–15% 明度铺底 |
| 强调色 | 关键数字/图形点缀 | 少量使用，勿与主色抢焦点 |
| 正文色 | 数据文字 | 与底色对比 ≥ 4.5:1（勿用浅灰当正文） |
| 次要文字色 | 辅注、说明、单位 | 中性灰（约 `#595959`），仅用于非关键信息 |
| 网格线 | 单元格分隔 | 极浅中性灰，弱于表头结构线 |
| 语义色 | 成功 / 警示 / 危险 | 低饱和底 + 深色字，成对使用（见 §5） |

### 字号阶梯（只用这几档）

| 用途 | 字号 | 字重 |
|------|------|------|
| 文档主标题 | 18–20 | 粗 |
| 区块/小节标题 | 12–13 | 粗 |
| 表头、数据正文 | 11 | 表头粗、正文常规 |
| 辅注、单位、脚注 | 10 | 常规或斜体 |

字体统一一种中文无衬线字体，整表一致，勿混用衬线/手写体。

### 行高与列宽节奏

- 主标题行 36–40，表头行 26–28，数据行 22–26。勿用默认行高堆砌。
- 列宽按内容：文本列 120–160，数量列 80，金额/单价列 110–120，状态列 90。
- 表头与数据区之间保持清晰的视觉分界（浅底或加粗下边线）。

## 2. 主题预设（推荐直接用）

spec 写 `"theme": "business"` 即可获得整套合规样式，无需逐个手写。可选：

| theme | 基调 | 适用 |
|-------|------|------|
| `business` | 企业蓝（默认） | 通用经营报表、销售单据、管理报表 |
| `finance` | 金融深蓝 + 低调金 | 财务、资金、审计类表格 |
| `fresh` | 清新绿 | 运营、库存、供应链、健康类 |
| `minimal` | 极简黑白 | 数据底稿、打印优先、正文型表格 |

主题提供的命名样式（单元格 `"style": "<名>"` 引用，也可被 spec 同名样式覆盖）：

| 样式名 | 用途 |
|--------|------|
| `title` / `subtitle` | 文档主标题 / 副标题（周期、单位、制表人） |
| `section` | 区块小标题（如「历史明细」） |
| `header` / `headerLeft` | 表头（居中 / 文本列左对齐） |
| `cell` / `cellText` | 数据格（居中 / 文本左对齐） |
| `qty` / `money` / `pct` / `date` | 数量 / 金额 / 百分比 / 日期专用格 |
| `total` / `totalMoney` | 合计行（标签 / 金额） |
| `zebra` / `zebraText` | 斑马纹行（居中 / 文本左对齐） |
| `note` | 辅注、脚注 |
| `success` / `warn` / `danger` | 语义底色格（状态、异常标记） |

`spreadsheet.py template --theme <名>` 可直接产出该主题的高质量样板，改内容即可用。

## 3. 版式结构（五段式）

成品的表格按五段组织，自上而下：

1. **标题区**：主标题（合并居中）+ 副标题（统计周期、单位、制表人）
2. **表头行**：浅底 + 主色字 + 粗体，文本列左对齐、数值列居中或右对齐
3. **数据区**：统一网格线；数值右对齐、整数居中、文本左对齐
4. **合计行**：加粗 + 主色浅底 + 结构线加强（与数据区明显区隔）
5. **辅注区**：单位、口径、公式说明，用 `note` 样式，与数据区之间留一空行

区块之间用 `section` 小标题分隔，勿把标题、表头、数据挤在一起。

## 4. 行分隔三选一（勿叠加）

| 方案 | 做法 | 适用 |
|------|------|------|
| 网格线 | 数据格带极浅四边线（主题默认） | 通用报表，最稳 |
| 斑马纹 | 交替行套 `zebra`/`zebraText`，其余行用 `cell`/`cellText` | 行数多、需要横向读行 |
| 三线表 | 仅保留表头上下线与合计上粗线，数据区无竖线 | 打印、正式文档 |

**反模式**：同时用网格线 + 斑马纹 + 加粗边框；彩色底 + 彩色边框 + 阴影叠加。

## 5. 对齐与数字格式

- 文本左对齐；数量居中；单价/金额右对齐；日期居中；百分比右对齐。
- 金额统一 `#,##0.00`；数量 `#,##0`；百分比 `0.0%`；编码/型号用强制文本（`"type": "text"`）保留前导零。
- 同一列只有一个数字格式，勿混排。
- 语义色用法：`success` 正常/已结算，`warn` 待处理/临界，`danger` 异常/超限；**底浅字深**，勿用饱和大红配白字满屏。

## 6. 条件格式与数据验证

- 条件格式优先用语义色（低饱和底 + 深色字 + 可选加粗），阈值为业务含义（超限、低于目标、异常波动）。
- 一列规则不超过两条；多条命中时用 `stopIfTrue` 控制优先级，避免颜色打架。
- 状态列用下拉（数据验证 `list`），选项 3–5 个为宜；输入提示写清楚口径。
- **下拉渲染保持默认「箭头」**（单元格显示文字 + 下拉箭头）。产品的下拉另有「芯片」样式会把单元格涂成灰底、文字对比度极低，自动生成场景勿用；如确需彩色芯片，必须在选项中逐项配色，保证文字与底色对比 ≥ 4.5:1。

## 7. 与数据区块联动

- 明细表（数据集绑定）与手工区之间留空行 + `section` 小标题，写清区块来源与刷新逻辑。
- 查询组件放在表格数据区上方或右侧空白列，**勿压住标题区与数据区**（默认落点 A1 会盖住主标题，应改到如右上空白处）。条件名写业务口径（如「下单日期」而非字段英文名）。
- 自动筛选只给范围，让使用者在表头勾选；预置条件会让表格一打开就处于"已筛选"状态，容易让人误以为数据缺失。

## 8. 交付前检查

- [ ] 一套主色贯穿；无多色混搭、无饱和深色块堆砌
- [ ] 字号只用四档；表头/正文/辅注层级清晰
- [ ] 数字对齐与格式统一；无浅灰正文
- [ ] 行分隔只用一种方案；合计行与数据区明显区隔
- [ ] 语义色成对（底浅字深）；条件格式阈值有业务含义
- [ ] 标题区含周期与单位；辅注说明公式与口径
